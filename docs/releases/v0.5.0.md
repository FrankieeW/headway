# Headway v0.5.0

This release combines fork/PR installation support with a project-wide reliability and contract
hardening pass. CLI, desktop and renderer changes share regression coverage.

## Highlights

- Installation evidence distinguishes an existing payload from a proven revision. Discover fork
  ancestry and install a reviewed PR's exact head SHA, including independent installations.
- Managed replacements retain durable recovery intent, recover interrupted swaps and keep uncertain
  bytes from being shown as a confirmed installed baseline. State writes retain a validated backup.
- Dry runs share the real validation/resolution path without saving subscriptions or installed/check
  state. Duplicate ids, destination conflicts and unusable asset recipes fail before approval.
- JSON/XML `ok` agrees with the exit status, including partial failures. Error codes remain stable;
  `config_changed`, `store_busy` and `recovery_pending` are additive. Batch and automatic updates
  retain completed outcomes when a later operation fails. Closed stdout pipes no longer panic.
- Shared check summaries and an IPC binding gate keep all desktop commands aligned with the renderer.
  Update admission, repeated quit, scheduler responsiveness and restart handling are regression-tested.
- Output lines, logs, events, downloads, API bodies and archive preflight have explicit resource
  budgets/deadlines. Transient git/HTTP failures have bounded retries; tag scans expose truncation.
- Missing GitHub digests produce visible warning evidence, not an integrity-success claim. GitHub token
  source variables are stripped from build/tool processes; request errors redact signed URL queries.
- The tray and notifications follow the saved English/Chinese preference. Optimistic switches roll back
  on failure, mock updates emit real lifecycle events, and idle status probing is reduced.
- Dependency advisories are remediated, CI actions are pinned, and native Apple Silicon/Intel release
  builds run artifact checks before publication. Release binaries have GitHub build provenance.

## Machine-consumer notes

Inspect the process exit code and top-level `ok`. Batch failures retain `data.results`; read each
item's `error.code`/`error.exit_code` and any completed `outcomes`. `next` is advisory, never proof that
an artifact was installed. Nested CLI commands add a `subcommand` path without renaming `command`.
Update outcomes may add `warnings`; clients should display these as text rather than ordinary
verified-success messages. See the updated agent skill and command tree for exact fields.

## Configuration and state

Absolute/`~/` paths and non-conflicting managed destinations are now checked on reads as well as
writes. Repair unsafe legacy hand-written config explicitly; Headway cannot infer the original cwd
of a relative destination. Unversioned state is migrated in memory, unsupported future state is left
untouched, and a corrupt state is not silently reset. Preserve it and inspect `state.json.bak` before
recovery. Deleting state discards installed provenance.

## Trust and release verification

Artifacts remain **ad-hoc signed and not notarized**: no Developer ID/notary credentials are available
for this repository. A digest or ad-hoc signature checks integrity, not publisher authenticity.
Source/package-manager builds still execute publisher code as your user, without a sandbox.
Read [the security model](../../SECURITY.md) before enabling unattended updates.

Download the artifact for your architecture together with `SHA256SUMS.txt`, then verify locally:

```sh
shasum -a 256 -c SHA256SUMS.txt --ignore-missing
gh attestation verify ./headway-aarch64-apple-darwin.tar.gz --repo FrankieeW/headway
```

Use the exact filename from the release for `gh attestation verify` (DMG, app ZIP or CLI tarball).
The checksum list is generated after both architecture artifacts are collected and is not itself
attested. Build provenance identifies the producing workflow/commit; it is not notarization.
