# Headway v0.5.1

This release adds read-only Homebrew ↔ GitHub source matching, release-aware commit history,
one-off install methods and direct editing of both GitHub install recipes, and completes the
engine and renderer dependency upgrades. Existing configuration and state remain compatible; see
the behavior changes to `edit` below.

## Homebrew ↔ GitHub matching

- Use `headway --json match brew:ripgrep`, `match cask:zed` or `match owner/repo` to find
  alternative sources with evidence and confidence levels. Matching never installs, tracks or
  switches a source automatically.
- `--offline` skips GitHub requests and token resolution while still reading local Homebrew
  metadata. Partial provider failures retain useful results and report `ok: false`.
- The desktop add/import flows offer the same suggestions for explicit selection. Homebrew
  discovery also reports repositories found in installed package metadata without GitHub requests.

## Release-aware commit history and one-off install methods

- Each commit of a page names the release that published it (`release_tag`, `release_url`,
  `can_download`). `commits --release`, `--tag '<regex>'` and
  `--ci success|failure|pending|not-run|unknown` narrow a page; the filters combine and
  `filtered_out` counts what they removed. The desktop history offers the same switch, tag field
  and CI dropdown.
- `update --method configured|source|asset` decides how one run installs: `asset` downloads the
  release that published the selected commit, so a commit-tracked app can install from its release
  without switching to release tracking. A forced asset install fails instead of falling back to a
  build. The method never rewrites the saved recipes. The desktop offers the choice next to its
  update buttons.

## GitHub install recipes

- `edit` can now change either saved recipe without switching the default: `--build`, `--preset`,
  `--workdir`, `--artifact`, `--keep-source` and `--source-root` edit the source recipe;
  `--pattern` and `--binary` edit the release recipe. Only `--method source|asset` changes which
  recipe ordinary updates use. With an asset default, `--build ''` removes the optional source
  recipe.
- Without `--method`, `add` builds from source when given `--build`, `--preset`, `--workdir` or
  `--artifact`.
- The desktop add/edit dialog edits both recipes and keeps the default when a recipe changes.

## Fixes and maintenance

- Preserve inventory identifiers and retained-backup digests with `sha2 0.11`. Both paths use the
  existing zero-padded lowercase SHA-256 encoder, so existing discovery identities and backup
  manifests remain compatible.
- Complete the React 19, i18next 26 and Lucide 1 upgrades. The repository link retains a local GitHub
  mark after Lucide's removal of brand icons.
- Migrate to Tailwind 4's PostCSS integration and Vite 8's Rolldown chunk groups. Retain the existing
  theme, animation plugin and theme-colored border defaults in light and dark mode.
- Support TypeScript 7 in both the renderer configuration and the IPC contract checker. The checker
  parses every API source, including files outside the tsconfig include globs, and still rejects
  missing handlers and incompatible argument names.
- Update Tauri plugins and SHA-pinned GitHub Actions. Dependabot groups minor/patch updates while
  leaving major upgrades enabled as independent PRs.

## Compatibility and security

No manual configuration or state migration is required. Additions: the CLI `match` command and
its IPC command; repository evidence in discovery results; the commit filters and their
`release_tag`, `release_url`, `can_download` and `filtered_out` fields; optional `filter` and
`method` arguments on the commit-list, plan and update IPC commands. Saving a GitHub app keeps the
active recipe in `install` and only the other method in `source_build` or `release_asset`, without
a duplicate of the active recipe.

Behavior changes for scripts and agents that call `edit`:

- `--build`, `--preset`, `--workdir` or `--artifact` no longer switch an app that downloads release
  assets to source builds; they edit its source recipe. Add `--method source` to switch.
- Flags for the recipe that is not the default now edit that recipe instead of failing with a
  usage error: `--pattern` or `--binary` on a source-build app save its release recipe, and
  `--method asset` with build flags keeps those flags on the source recipe.

Headway ships only for macOS. The `glib 0.18.5` advisory `GHSA-wrw7-89jp-8q8g` belongs to Tauri's
unshipped Linux GTK/WebKitGTK graph and is absent from both shipped macOS dependency graphs. Its
alert is classified as **not used**, not patched; reassess it before adding Linux support. See
[SECURITY.md](../../SECURITY.md).

## Downloads and verification

Choose Apple Silicon (`arm64` / `aarch64-apple-darwin`) or Intel (`x64` / `x86_64-apple-darwin`).
The app and CLI remain **ad-hoc signed and not notarized**. Ad-hoc signatures check integrity, not
publisher identity; do not disable Gatekeeper globally.

Download the matching artifact and `SHA256SUMS.txt` from the release, then verify the checksum and
GitHub build provenance:

```sh
shasum -a 256 -c SHA256SUMS.txt --ignore-missing
gh attestation verify ./headway-aarch64-apple-darwin.tar.gz --repo FrankieeW/headway
```

Use the exact downloaded filename for provenance verification; DMGs, app ZIPs and CLI tarballs are
attested. The checksum manifest itself is not attested.
